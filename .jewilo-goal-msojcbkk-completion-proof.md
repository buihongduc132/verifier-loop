## Root Causes Identified

### 1. round_recover Path Mismatch Bug
**Problem**: `round_recover::status()` and `recover()` used legacy `v{i}` verifier ids with no phase context, but the dynamic pipeline stores verdicts at `rounds/{N}/{phase}/{role}{i}/verdict.json`.

**Impact**: Goals that timed out before completion could not be recovered because RECOVER couldn't find the verdicts (looking in wrong paths).

**Evidence**: Goal `1e373ba2-8468-427a-bd6b-9227c25872b1` had 3 APPROVE verdicts at `rounds/1/1a/{d1,d2,d3}/verdict.json`, but RECOVER read from `rounds/1/{v1,v2,v3}/` → found nulls → moved to round 2.

### 2. bhd-litellm/rag-quick Model Fallback Chain Dead
**Problem**: Primary rag-quick deployments rate-limit occasionally. Fallback chain points to dead endpoints:
- `chutes/Qwen/Qwen3-32B-TEE`: 402 (account balance $0)
- `llmgateway-free`: no API key configured

**Impact**: Verifiers timed out when all primary deployments were busy and fallbacks failed.

**Solution**: Changed `dumpAdapter` from `pi-rag-quick` to `pi` (uses role-smart with working fallbacks).

### 3. hermes-verifier Adapter Missing
**Problem**: No ACP-compatible adapter for hermes existed in jewilo.

**Solution**: Created `~/.local/bin/hermes-verifier` wrapper that:
- Reads prompt from stdin
- Runs `hermes -z` with meta-prompt instructing to call `jewije`
- Emits ACP JSON events (session, agent_start, agent_end)
- Propagates all VERIFIER_LOOP_* env vars

### Fix 2: hermes-verifier Wrapper
**File**: `~/.local/bin/hermes-verifier`

**Implementation**: Python wrapper that bridges jewilo's stdin-based ACP protocol with hermes.

**Key Features**:
- Reads verifier prompt from stdin (jewilo pipes the full prompt)
